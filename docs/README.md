# Docs

## Recording a demo GIF

The README currently proves itself with **real dogfood PRs** (see PR #6) rather
than an embedded GIF, but a short demo GIF is still the strongest visual for
showcasing the tool in launch threads and tweets.

Suggested flow:

1. Create a throwaway demo repo that **uses** this action (point `uses:` at your
   branch: `Akimiya-z/codex-guard@main`).
2. Open a PR `from: codex/feat/demo` with a title like `refactor: generated by
   Codex`, and push a diff containing:
   - a `// TODO: real work here` comment,
   - an obvious dummy credential in an added line,
   - one commit with a sloppy subject,
   - (optionally) break one CI step.
3. Record the screen from "PR opened" through the failing `Codex Guard` check
   and its inline annotations.
4. Record a *second* clip where the findings are fixed and the check goes green —
   showing the pass path doubles the value.

Tools: `asciinema` + [`agg`](https://github.com/asciinema/agg) for terminal
casts, or any macOS recorder (`screencapture`, QuickTime Player) for UI-based
demos. Keep it under ~20 seconds and mute audio.

```bash
# asciinema + agg quick path
asciinema rec demo.cast
agg demo.cast docs/demo.gif
```

## Verifying the whole action locally

You can run the action's orchestration outside GitHub with an injected fake
client — `test/main.test.js` does exactly that:

```bash
npm test
```

For a manual smoke test against real GitHub, create a throwaway repo, wire the
workflow, and push a deliberately messy agent-style PR. The check run +
annotation + comment should appear within ~1 minute.
