🤖 Codex Guard

An automatic quality gate for AI-generated pull requests. TODO leftovers, leaked secrets, sloppy commits and red CI never reach main — and human review bandwidth goes to design, not cleanup.

GitHub repo README Releases

What it does

Runs on pull_request, figures out whether the PR looks agent-written (label, branch prefix, or title), and gates it on four deterministic checks — so human-authored PRs pass untouched by default, and only agent PRs get the gate:

CheckWhat it flags
🧹 TODO scanTODO / FIXME / XXX / HACK / WIP on added lines only
🔐 Secret scanAWS / GitHub / Google / OpenAI / Anthropic / Slack / Stripe keys, hardcoded credentials, connection strings — values redacted
💬 Commit hygieneNon-conventional and empty commit subjects
🧪 CI statusFailing status checks or check runs on the PR head commit

Every finding lands as a file/line check-run annotation plus one living report comment that updates in place. Optionally submits a formal REQUEST_CHANGES review.

Honest coverage: binary and very large files may not include a text patch in GitHub's API. Codex Guard reports exactly how many eligible files were scanned, lists unavailable paths, and returns a neutral warning instead of silently claiming complete coverage.

30-second setup

Run this from the root of your Git repository:

npx --yes codex-guard init
git add .github/workflows/codex-guard.yml
git commit -m "ci: add Codex Guard"

The generated workflow starts in observe mode: it annotates findings without blocking merges while you tune the policy. Use npx --yes codex-guard init --strict to enforce from the first run.

When you are ready to enforce, set soft-fail to 'false', then require the Codex Guard status check under Settings → Branches → Require status checks.

Per-repo policy

Override any input from .github/codex-guard.yml on the default branch — policy lives in the repo, and agents can't loosen it from inside their PR:

gate-agents-only: true
fail-on:
  - secrets
  - commits
  - ci
comment-mode: replace
request-changes: true

Local dry-run (CLI)

The same CLI also runs checks locally before CI:

git diff origin/main > /tmp/patch.diff
npx --yes codex-guard --diff /tmp/patch.diff
# or straight against a ref (bare --git scans uncommitted changes):
node src/cli.js --git --commits

Exit codes: 0 = no blocking findings, 1 = blocking findings, 2 = usage error. --json mirrors the findings-json output.

Agent skill

Pack the pre-submit checks as a skill so Codex or Claude Code run them themselves before opening a PR:

bash skills/install.sh      # installs for Codex and Claude Code

The agent runs node src/cli.js --git --commits, fixes findings, and only submits a clean diff. CI then never sees what should have been caught earlier.

Sweep existing PRs

Adopting the gate doesn't have to be retrospective — one workflow_dispatch run inspects every currently-open agent PR and writes a report:

on:
  workflow_dispatch:
jobs:
  sweep:
    runs-on: ubuntu-latest
    steps:
      - uses: Akimiya-z/codex-guard@v1
        with:
          sweep: 'true'
